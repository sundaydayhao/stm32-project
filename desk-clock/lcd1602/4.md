• 如果改用 ESP32，成本不一定明显上升，要看你是不是还保留 DS3231。

  按 2026-03-31 查到的价格粗算：

  - STM32F103C8T6 开发板 约 ¥11.46
  - ESP32-WROOM-32 模组 约 ¥16.9
  - DS3231 模块 约 ¥14.9

  所以有 3 种情况：

  - STM32 + DS3231 改成 ESP32 + DS3231：大约 +¥5~8
  - STM32 + DS3231 改成 ESP32 + 纯NTP：大概率 持平，甚至可能 略降
  - STM32 + 无RTC 改成 ESP32 + NTP：大约 +¥5~10

  如果你是卖成品，我更建议 ESP32 + DS3231，不是因为必须，而是因为它最稳：

  - 有网时自动 NTP 校时
  - 没网或断网时 RTC 顶上
  - 客户体验明显比“纯联网钟”更像成品

  时间设置不要按“城市名”硬编码，应该按 时区 设置。
  更准确地说：设备先用 NTP 拿 UTC，再根据用户保存的 TZ 规则换算成本地时间。ESP-IDF 官方
  就是这么做的：setenv("TZ", ...) 然后 tzset()，之后 localtime() 会自动按时区和夏令时出
  本地时间。

  实际产品建议这样做：

  - 中国版：不用选城市，直接固定 CST-8
  - 海外版：让客户在首次开机时选 时区，不是选城市
  - 最简单可做成 6 个选项：Eastern / Central / Mountain / Pacific / Arizona / Hawaii
  - 选择结果存进 NVS，后面每次开机自动套用

  美国夏令时不要自己手写“3月加1小时、11月减1小时”的业务代码，直接用 TZ 规则字符串。
  按 NIST 当前规则，2026 年美国 DST 是：

  - 2026-03-08 02:00 开始
  - 2026-11-01 02:00 结束

  常用写法可以直接存这些：

  - 美东：EST5EDT,M3.2.0/2,M11.1.0/2
  - 美中：CST6CDT,M3.2.0/2,M11.1.0/2
  - 美山：MST7MDT,M3.2.0/2,M11.1.0/2
  - 美西：PST8PDT,M3.2.0/2,M11.1.0/2
  - 亚利桑那：MST7
  - 夏威夷：HST10

  注意：

  - Arizona 大部分地区 不执行夏令时
  - Hawaii 不执行夏令时
  - Navajo Nation 是亚利桑那里的特殊例外，会执行夏令时

  如果你是做售卖版，我会建议你定成这个逻辑：

  - 默认方案：ESP32 + DS3231
  - 首次开机：配网 + 选时区
  - 平时运行：优先 NTP，同步后回写 RTC
  - 断网时：RTC 继续走
  - 用户界面：再保留一个“手动校时/改时区”入口

  这样基本能把“客户收到后时间不准”和“美国夏令时切错”两个问题一起解决。
